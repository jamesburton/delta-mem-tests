# Resume context — OSCAR INT2 + delta-mem combo characterised; pivot to Strix Halo

## TL;DR

48 h of optimisation closed the headline OSCAR INT2 + delta-mem
reproduction (Appendix D of `report/tier1-summary.md`):

- **Production combo** (OSCAR INT2 + GPQA-cal rotation + packing +
  cross-arm invalidation + shadow ON, conv-26/10 q, 17 590 tokens):
  base 0.2735 / delta 0.3642 / **ratio 1.332** (paper claims 1.20).
- **INT2 codes pack 4-per-byte** (submodule `cd17cb3`) → **7.1× memory**
  vs bf16 at the cache level. End-to-end this freed ~2.1 GB, taking the
  12 GB card from OOM-risky to comfortable headroom.
- **OSCAR INT4 line was investigated and dropped** (v4a: base lifts
  +19 %, delta drops -34 %, ratio collapses to 0.71 because delta-mem
  was trained against INT2's noisier representation).
- **Context-scaling sweep** found the binding constraint is the
  **delta-mem adapter's training-context distribution**, not VRAM:
  at 17 k ratio = 1.33, at 25 k ratio = 0.60 (delta arm -62 %).

## What's next: train a longer-context delta-mem adapter

The next real win is **retraining/fine-tuning** the delta-mem adapter
on long-context data (LongMemEval / InfBench mix) so it stays useful
past 20 k. That training is infeasible on this 12 GB host but well
within Strix Halo's 96 GB unified VRAM.

**Full plan: [`STRIX_INSTRUCTIONS.md`](../STRIX_INSTRUCTIONS.md).**

Key points:

- Adapter weights are framework-portable safetensors. Train on
  ROCm/Strix Halo, deploy on CUDA here — no conversion needed.
- Start by fine-tuning from the published adapter
  (`declare-lab/delta-mem_qwen3_4b-instruct`); preserve the 17 k anchor.
- Phase 1 target 32 k context, phase 2 push 64 k.
- Validate every checkpoint here against conv-26/10 q (anchor) and
  conv-41/10 q (extension).

## Hard-earned lessons (do not forget)

- **`locomo_eval.py` reuses existing output JSONs** rather than re-running.
  Always `mv outputs/<name>.json outputs/<name>.STALE.json` before relaunching.
  This bit us once (v4a "result" was stale).
- **Cross-arm cache invalidation** is required between base ↔ delta arms
  for any non-bf16 KV backend. Already wired in commit `35612a4`.
- **Set `OSCAR_K_ROTATION_PATH` and `OSCAR_V_ROTATION_PATH`** every time
  the OSCAR backend is used; the runner errors out without them.
- **Transient CUDA "unknown error" crashes** are a known nuisance on this
  driver after long runs. Almost always fixed by re-running; not a
  code bug.
