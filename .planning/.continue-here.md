## Important finding (so we don't relearn it next time)

The initial port baked rotations into the projection weights. This was wrong
for Qwen3 because of **QK Norm + RoPE**:

```python
query_states = self.q_norm(self.q_proj(x).view(hidden_shape))...     # QK Norm
key_states   = self.k_norm(self.k_proj(x).view(hidden_shape))...     # QK Norm
query_states, key_states = apply_rotary_pos_emb(q, k, cos, sin)      # RoPE
```

Neither the per-channel γ scale inside q_norm/k_norm nor RoPE commute with
an arbitrary orthogonal R, so pre-multiplying R into `q_proj.weight` /
`k_proj.weight` produces gibberish at inference (rotation-only output
collapsed to repeated '?' tokens before the fix). V has no such
preprocessing, so V-side baking would be valid, but we use inline-rotation
uniformly for API symmetry.

The correct implementation is `apply_rotations()` — register per-layer
rotation buffers on each `self_attn` module, monkey-patch
`Qwen3Attention.forward` once per class to inject the rotation between RoPE
and `past_key_values.update`, and un-rotate `attn_output` before `o_proj`.
The full reasoning is in the submodule commit message at `55760e2`.

## Critical anti-patterns (extending the prior list)

| Pattern | What happened | Mitigation |
|---------|---------------|------------|
| Test rotation invariance on a stub attention block | The stub had no q_norm/k_norm/RoPE, so it passed against a broken implementation that produced gibberish on the real model | Always test against a real `Qwen3Attention` module from `transformers.models.qwen3.modeling_qwen3` |
| Pre-multiply rotation into `q_proj.weight` / `k_proj.weight` on a QK-Norm model | q_norm's per-channel γ doesn't commute with rotation; output collapses to '?' | Use `apply_rotations` (attention-forward monkey-patch); never `bake_rotations` |
| Treat a short-prompt smoke as proof of INT2 quality | Prompts under `sink_tokens=64` never populate the INT2 middle region; the smoke validates rotation only | Either run a smoke with a ~1k+ token prompt, or trust nothing until the LoCoMo conv-0 number lands |
